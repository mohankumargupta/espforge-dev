# `i2cfix.md`

> **Design & Implementation Specification**  
> **Topic:** True Single-Source-of-Truth I2C Architecture: Addressed `I2cDevice`, Multi-Drop Bus Sharing, and Scanner Support  
> **Status:** Draft / Ready for Implementation  
> **Target Crates:** `espforge-runtime`, `espforge-schema`, `espforge-elements`, `espforge-drivers`, `espforge-examples`

---

## 1. Executive Summary & Problem Analysis

In `espforge`, every generated project contains the contract:
> `// GENERATED BY ESPFORGE — DO NOT EDIT. Source of truth is the project .espf file.`

Currently, the I2C subsystem breaks this contract in multiple fundamental ways:

1. **The "Phantom Address" Bug:**
   A user declares an address in `.espf`:
   ```text
   <i2c_component id="oled_bus" i2c="$i2c0" address="0x3C" />
   ```
   `espforge-elements/src/components/i2c.rs` parses `address="0x3C"`, but in `emit()`, **`address` is completely discarded**. The generated `Components` struct contains an unaddressed `espforge_runtime::I2cBus`.
2. **Hardcoded Addresses in Application Code (`app.rs`):**
   Because `I2cBus` has no concept of an assigned address, users are forced to re-type the slave address in Rust:
   ```rust
   // app.rs: 0x42 was already in .espf, but user must write it again here!
   i2c.write_read(0x42, &[sent_byte], &mut buffer);
   ```
3. **Hardcoded Addresses in Device Drivers (`espforge-drivers`):**
   In `espforge-drivers/src/scd4x.rs`:
   ```rust
   pub const ADDRESS: u8 = 0x62; // Hardcoded in driver, completely ignoring .espf
   ```
   If a user configures address pin jumpers on hardware to change an address, updating the address in `.espf` does nothing because the driver ignores it.
4. **The Multi-Drop Prohibition Bug (`E0611`):**
   In `espforge-elements/src/components/i2c.rs`:
   ```rust
   if let Some(other) = used_by(cx, bus) {
       return Err(cx.report(codes::COMPONENT_I2C_BUS_USED, ...));
   }
   ```
   I2C is by definition a multi-drop bus. However, `espforge` emits a fatal error `COMPONENT_I2C_BUS_USED` if more than one component connects to the same physical I2C controller. Connecting an OLED display (`0x3C`) and a sensor (`0x62`) to the same I2C controller is currently rejected by the compiler.
5. **Architectural Asymmetry with SPI:**
   In SPI, `# peripherals` declares `<spi>` (the bus wires SCLK/MOSI/MISO), and `# components` declares `<spi_component cs="$gpio9">` (the device endpoint with its chip select). Multiple SPI components can share one SPI peripheral. In I2C, `<i2c_component>` currently claims the entire bus exclusively and throws away its device selector (`address`).

## 2. Core Architectural Principles

1. **Hardware Controller vs. Addressed Device Endpoint:**
   - **`# peripherals` (`<i2c>`):** Represents the physical hardware controller peripheral (`I2C0`, `I2C1`) and its bus pins (`sda`, `scl`) and bus frequency (`frequency="400kHz"`). It has **no slave address**.
   - **`# components` (`<i2c_component>`):** Represents an **addressed device endpoint** on that bus (e.g. `address="0x3C"`).
2. **Multi-Drop by Default:**
   Multiple `<i2c_component>` endpoints can bind to the same `<i2c>` peripheral.
3. **Address Conflict Detection:**
   Two `<i2c_component>` elements on the *same* `<i2c>` controller **cannot share the same 7-bit slave address**. Collision is an error detected at lower-time (`codes::CONFLICT_I2C_ADDRESS`). Two components on *different* I2C controllers *can* share the same address.
4. **Unaddressed Bus Exception for Scanners:**
   Bus-level diagnostic utilities like an I2C scanner do not talk to a fixed slave address. An `<i2c_component>` without an `address` attribute provides raw, unaddressed bus access (`I2cBus`), allowing dynamic address sweeping (`for addr in 1..127 { bus.write(addr, &[]) }`).
5. **No Address Duplication in Driver Crates:**
   Device drivers in `espforge-drivers` must receive their target slave address from the component or bind to an addressed `I2cDevice`, eliminating hardcoded address constants in drivers.

## 3. Element & Schema Specifications

### 3.1 `# peripherals` (`<i2c>`) — Unchanged
`<i2c>` defines the bus controller, physical pins, and frequency:

```kdl
element "i2c" section="peripherals" {
    summary "I2C bus controller"
    description "Declares an I2C controller and pins. Referenced by components via i2c=\"$id\"."
    attr "id" kind="ident" required=#true
    attr "sda" kind="pin" required=#true
    attr "scl" kind="pin" required=#true
    attr "frequency" kind="freq" default="100kHz"
    example "minimal" #"<i2c id="i2c0" sda="6" scl="7" />"#
    example "high speed" #"<i2c id="i2c0" sda="6" scl="7" frequency="400kHz" />"#
}
```

### 3.2 `# components` (`<i2c_component>`) — Clarified Semantics
`address` remains an optional attribute.
- When `address` is specified (e.g. `address="0x3C"`): it generates an addressed **`I2cDevice`**.
- When `address` is omitted: it generates an unaddressed **`I2cBus`** (scanner / raw mode).

```kdl
element "i2c_component" section="components" {
    summary "An addressed device endpoint or raw bus handle on an I2C controller"
    description "Binds an I2C bus with a 7-bit slave address. Omit address for raw unaddressed bus access (e.g. scanner)."
    attr "id" kind="ident" required=#true
    attr "i2c" kind="ref" to="i2c" required=#true {
        help "The I2C bus controller peripheral in # peripherals."
    }
    attr "address" kind="hex" {
        help "7-bit slave address (e.g. 0x3C). Omit for raw unaddressed bus access (I2C scanner)."
    }
    example "sensor endpoint" #"<i2c_component id="temp_sensor" i2c="$i2c0" address="0x48" />"#
    example "raw scanner" #"<i2c_component id="bus_scanner" i2c="$i2c0" />"#
}
```

## 5. Runtime Architecture (`espforge-runtime`)

### 5.1 `I2cBus` vs `I2cDevice` in `espforge-runtime/src/hw/i2c.rs`

Split I2C support into two types:
1. **`I2cBus<Dm>`**: The raw controller (shared, reference-counted or statically held in a `RefCell` or `Mutex`).
2. **`I2cDevice<Dm>`**: A specific device on that bus holding an immutable slave address.

```rust
// espforge-runtime/src/hw/i2c.rs

/// An addressed device endpoint on an I2C bus.
/// Holds a lightweight Copy handle to the shared I2cBus and a fixed 7-bit address.
#[derive(Clone, Copy)]
pub struct I2cDevice<Dm: DriverMode + 'static> {
    bus: I2cBus<Dm>,
    address: u8,
}

impl<Dm: DriverMode + 'static> I2cDevice<Dm> {
    /// Create a new addressed device on `bus` targeting `address`.
    pub const fn new(bus: I2cBus<Dm>, address: u8) -> Self {
        Self { bus, address }
    }

    /// Returns the 7-bit address configured from .espf.
    pub const fn address(&self) -> u8 {
        self.address
    }

    /// Access the underlying raw unaddressed bus.
    pub const fn bus(&self) -> I2cBus<Dm> {
        self.bus
    }
}
```

### 6.1 `I2cComponent` Struct in `espforge-elements/src/components/i2c.rs`

```rust
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct I2cComponent {

}
```

### 6.2 Lowering Logic: Allow Multi-Drop, Reject Address Collisions

In `I2cComponentElement::lower`:

1. **Delete the singleton check:** Remove `if let Some(other) = used_by(cx, bus) { ... }`.
2. **Validate Address Bounds:**
   ```rust
   if let Some(addr) = address {
       if addr == 0 || addr > 0x7F {
           return Err(cx.report(
               codes::I2C_INVALID_ADDRESS,
               span_of(node, "address"),
               "invalid i2c address",
               format!("<i2c_component id=\"{}\"> address=\"0x{:02x}\" must be a 7-bit address in 0x01..=0x7F", id.raw, addr),
           ));
       }
   }
   ```
3. **Validate Address Collisions on the Same Bus:**
   ```rust
   if let Some(addr) = address {
       for component in cx.components() {
           if let Component::I2c(existing) = component {
               if existing.bus == bus && existing.address == Some(addr) {
                   return Err(cx.report(
                       codes::CONFLICT_I2C_ADDRESS,
                       node_span(node),
                       "i2c address conflict",
                       format!(
                           "<i2c_component id=\"{}\"> and <i2c_component id=\"{}\"> both use address 0x{:02x} on <i2c id=\"{}\">",
                           existing.id.rust_name(),
                           id.raw,
                           addr,
                           cx.bus(bus).unwrap().id().raw
                       ),
                   ));
               }
           }
       }
   }
   ```
4. **Push Component:**
   ```rust
   cx.push(Component::I2c(I2cComponent { id, bus, address }));
   ```

### 6.3 Code Generation in `I2cComponent::emit`

Just like SPI uses `cx.once()` for `let spi2_bus = SpiBus::build(...)`, I2C now uses `cx.once()` for building the shared controller **once per used bus**.

Each component field is then initialized as either an addressed `I2cDevice` or an unaddressed `I2cBus`:

```rust
impl Lowered for I2cComponent {
    fn id(&self) -> &Ident {
        &self.id
    }

    fn emit(&self, board: &Board, cx: &mut EmitCx) {
        let Some(Bus::I2c {
            id: bus_id,
            peripheral,
            sda,
            scl,
            khz,
            ..
        }) = board.resources.bus(self.bus)
        else {
            return;
        };

        let handle = format_ident!("{}_bus", bus_id.rust_name());
        let runtime = runtime_type(board.meta.runtime);
        let peripheral_tokens = peripheral_access(peripheral);
        let (sda_pin, scl_pin) = (sda.pin().0, scl.pin().0);
        let sda_tokens = gpio(sda_pin);
        let scl_tokens = gpio(scl_pin);
        let rate_tokens = rate(*khz);

        // 1. Emit the shared bus controller once in the prelude
        let key = handle.to_string();
        let inserted = cx.once(
            &key,
            quote! {
                let #handle = espforge_runtime::I2cBus::build(
                    #peripheral_tokens,
                    #sda_tokens,
                    #scl_tokens,
                    espforge_runtime::I2cConfig { frequency: #rate_tokens },
                )
                .expect("I2C bus configuration failed");
            },
        );

        if inserted {
            cx.safety_block(
                format!("let {handle} ="),
                &[
                    "SAFETY: espforge checked that no other component uses this",
                    &format!("peripheral or GPIO{sda_pin}/GPIO{scl_pin}."),
                ],
            );
        }

        // 2. Emit the component field on Components struct
        let name = format_ident!("{}", self.id.rust_name());
        match self.address {
            Some(addr) => {
                let addr_lit = Literal::u8_unsuffixed(addr);
                cx.field(quote! {
                    pub #name: espforge_runtime::I2cDevice<#runtime>,
                });
                cx.init(quote! {
                    #name: espforge_runtime::I2cDevice::new(#handle, #addr_lit),
                });
            }
            None => {
                // Raw scanner / unaddressed bus handle
                cx.field(quote! {
                    pub #name: espforge_runtime::I2cBus<#runtime>,
                });
                cx.init(quote! {
                    #name: #handle,
                });
            }
        }
    }
}
```

## 7. Driver Updates (`espforge-drivers`)

### 7.1 Sensirion SCD4x Driver (`espforge-drivers/src/scd4x.rs`)

Delete the hardcoded `ADDRESS` constant from `scd4x.rs`. The driver now takes `I2cDevice<Blocking>`:

```rust
// espforge-drivers/src/scd4x.rs

pub struct Scd4x {
    device: I2cDevice<Blocking>,
}

impl Scd4x {
    /// Take the addressed device handle from Components.
    pub fn new(device: I2cDevice<Blocking>) -> Self {
        Self { device }
    }

    pub fn start(&mut self) -> Result<(), Scd4xError> {
        self.command(START_PERIODIC_MEASUREMENT)
    }

    pub fn stop(&mut self) -> Result<(), Scd4xError> {
        self.command(STOP_PERIODIC_MEASUREMENT)
    }

    pub fn read(&mut self) -> Result<Measurement, Scd4xError> {
        let command = READ_MEASUREMENT.to_be_bytes();
        let mut raw = [0u8; 9];
        // Address is known by self.device!
        self.device
            .write_read(&command, &mut raw)
            .map_err(|_| Scd4xError::Bus)?;
        
        let co2 = word(&raw[0..3])?;
        let temperature = word(&raw[3..6])? as i16;
        let humidity = word(&raw[6..9])?;
        Ok(Measurement {
            co2_ppm: co2,
            temperature_centi_c: (temperature as i32 * 17_500 / 65_536 - 4_500) as i16,
            humidity_centi_percent: (humidity as u32 * 10_000 / 65_536) as u16,
        })
    }

    fn command(&mut self, command: u16) -> Result<(), Scd4xError> {
        self.device
            .write(&command.to_be_bytes())
            .map_err(|_| Scd4xError::Bus)
    }
}
```

### 7.2 SSD1306 Display Driver (`espforge-drivers/src/ssd1306.rs`)

`ssd1306`'s `I2CDisplayInterface::new` accepts any struct that implements `embedded_hal::i2c::I2c`. Because `I2cDevice` implements `embedded_hal::i2c::I2c` by utilizing its configured address, `Ssd1306Display` receives `I2cDevice<Blocking>` directly:

```rust
// espforge-drivers/src/ssd1306.rs

pub struct Ssd1306Display<SIZE: ssd1306::prelude::DisplaySize> {
    display: Oled<SIZE>,
}

impl<SIZE: ssd1306::prelude::DisplaySize> Ssd1306Display<SIZE> {
    /// Build the panel on the addressed device handle and run initialization.
    pub fn new(device: I2cDevice<Blocking>, size: SIZE, rotation: DisplayRotation) -> Self {
        let interface = ssd1306::I2CDisplayInterface::new(device);
        let mut display =
            ssd1306::Ssd1306::new(interface, size, rotation).into_buffered_graphics_mode();
        display.init().expect("SSD1306 OLED initialization failed");
        Self { display }
    }
    ...
}
```

## 9. Migration & Step-by-Step Execution Plan

### Step 1: `espforge-diagnostics`
- Add `CONFLICT_I2C_ADDRESS` (`E0708`) and `I2C_INVALID_ADDRESS` (`E0516`) to `codes.rs`.
- Retire `COMPONENT_I2C_BUS_USED` (`E0611`).

### Step 2: `espforge-runtime`
- In `src/hw/i2c.rs`:
  - Define `pub struct I2cDevice<Dm> { bus: I2cBus<Dm>, address: u8 }`.
  - Implement curried `write`, `read`, `write_read`, and `transaction` on `I2cDevice<Blocking>` and `I2cDevice<Async>`.
  - Implement `embedded_hal::i2c::I2c` and `embedded_hal_async::i2c::I2c` for `I2cDevice`.
  - Re-export `I2cDevice` from `src/hw/i2c.rs` and `src/lib.rs`.

### Step 3: `espforge-elements`
- In `src/components/i2c.rs`:
  - Remove the singleton check (`E0611`).
  - Add 7-bit address range check (`0x01..=0x7F`) emitting `E0516`.
  - Add address collision detection across components on the same bus emitting `E0708`.
  - Update `I2cComponent::emit`:
    - Use `cx.once(&key, ...)` to emit `let <bus_id>_bus = I2cBus::build(...)` in the prelude.
    - If `address.is_some()`: emit field as `I2cDevice<#runtime>` and init as `I2cDevice::new(#handle, #addr)`.
    - If `address.is_none()`: emit field as `I2cBus<#runtime>` and init as `#handle`.

### Step 4: `espforge-drivers`
- In `src/scd4x.rs`:
  - Change `Scd4x::new` to accept `I2cDevice<Blocking>`.
  - Remove `pub const ADDRESS: u8 = 0x62;` and use `self.device.write_read(...)` and `self.device.write(...)`.
- In `src/ssd1306.rs`:
  - Change `Ssd1306Display::new` to accept `I2cDevice<Blocking>`.
